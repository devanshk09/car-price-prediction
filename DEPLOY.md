# Deploying to AWS with a CI/CD pipeline (Free Tier)

```
                                         ┌──────────────────────────┐
                                         │  S3 model bucket         │
                                         │  models/builds/<n>/      │
                                         │  models/latest/          │
                                         └───▲──────────────┬───────┘
                                   upload    │              │  download on start-up
                                   model     │              ▼
GitHub push ──► CodePipeline ──► CodeBuild ──┴────────► CodeDeploy ──► EC2 t3.micro
                (watches repo)   install, train, test    copies app,     Ubuntu 24.04,
                                 → upload model to S3    runs scripts/   systemd + uvicorn :80
```

Each `git push` to `main` retrains the model and runs the tests. If they pass, it
**stores the model in S3** and redeploys the site. The server then downloads
exactly the model that build tested. Use **one region for everything**. These
steps use **Asia Pacific (Mumbai) `ap-south-1`**.

**How S3 is used**
1. **Model store (your bucket):** every trained model is versioned by build number, with `models/latest/` as a pointer. The app on EC2 loads its model from here.
2. **Pipeline artifacts (created automatically by CodePipeline):** holds the source and build zips passed between stages.

Files this setup uses:

| File | Purpose |
|---|---|
| `buildspec.yml` | CodeBuild: install → train → test → upload model to S3 → package app |
| `appspec.yml` | CodeDeploy: where to copy files, which scripts to run |
| `scripts/*.sh` | Stop app → clean folder → install packages → start → health-check |
| `deploy/car-price.service` | systemd unit that keeps uvicorn running on port 80 |
| `deploy/app.env` | *Generated by CodeBuild:* the S3 bucket and model path for this deployment |
| `deploy/ec2-user-data.sh` | One-time EC2 setup: Python, swap, CodeDeploy agent |

## 0. Before you start: protect yourself from charges

1. **Check which free tier you have.** Go to Billing and Cost Management → *Free Tier*.
   - Account created **before 15 Jul 2025**: you're on the *legacy 12-month free tier* (750 h/month of t2.micro/t3.micro, 5 GB S3).
   - Account created **on or after 15 Jul 2025**: you're on the *Free plan* ($100–200 credits, lasts 6 months or until the credits run out). The account closes at the end unless you upgrade.
2. **Create a zero-spend budget.** Go to Billing → *Budgets* → Create budget → template **Zero spend budget** and enter your email. AWS will then email you the moment anything costs money.
3. Pick **Asia Pacific (Mumbai)** in the region selector (top-right) and keep it there for every step.

## 1. Push the project to GitHub

```powershell
cd car-price-prediction
git init
git add .
git commit -m "Car price prediction with CI/CD"
git branch -M main
git remote add origin https://github.com/<you>/car-price-prediction.git
git push -u origin main
```

`.gitattributes` keeps the `.sh` scripts in Linux format, and `buildspec.yml` also strips Windows line endings
and sets execute permission, so committing from Windows is safe.

The model file in `models/` is in Git only so the app runs on your laptop. The deployed server never uses it; it downloads the model from S3.

## 2. Create the S3 model bucket

S3 → **Create bucket**:

| Setting | Value |
|---|---|
| Bucket type | General purpose |
| Name | Must be unique worldwide, e.g. `car-price-models-dev-2026` |
| Region | Asia Pacific (Mumbai) `ap-south-1` |
| Block *all* public access | **On** (default). Only your build and your server need it. |
| Versioning | Off (each build already gets its own folder) |
| Encryption | Default (SSE-S3) |

**Write the bucket name down.** You need it in steps 3 and 6.

Then open the bucket → *Management* → **Create lifecycle rule**:
- Name `expire-old-models`, scope *Limit to prefix* `models/builds/`
- *Expire current versions of objects* after **30 days**

This keeps storage tiny. `models/latest/` is not affected.

## 3. Create two IAM roles

In IAM → *Roles* → **Create role**:

**a) Role for the EC2 instance:** `CarPriceEC2Role`
- Trusted entity: *AWS service* → **EC2**
- Permissions: `AmazonEC2RoleforAWSCodeDeploy` (lets the instance read from S3, which covers both deploy bundles and your model bucket) and `AmazonSSMManagedInstanceCore` (lets you open a browser terminal without SSH keys)

**b) Role for CodeDeploy:** `CarPriceCodeDeployRole`
- Trusted entity: *AWS service* → **CodeDeploy** → use case *CodeDeploy*
- Permissions: `AWSCodeDeployRole` (pre-selected)

CodeBuild and CodePipeline create their own roles in step 6. You'll give the CodeBuild role S3 upload permission there.

## 4. Launch the EC2 instance

EC2 → **Launch instance**:

| Setting | Value |
|---|---|
| Name | `car-price-server` |
| Tags (*Add additional tags*) | Key `App`, Value `car-price` (CodeDeploy finds the server by this tag) |
| AMI | **Ubuntu Server 24.04 LTS** (marked *Free tier eligible*) |
| Instance type | **t3.micro** (free-tier eligible on both old and new accounts) |
| Key pair | Create one (optional; you can also connect via EC2 Instance Connect or Session Manager) |
| Network → Security group | Allow **HTTP (80) from Anywhere**. Allow SSH (22) from **My IP** only |
| Auto-assign public IP | Enable |
| Storage | 8–20 GiB **gp3** (30 GiB is free) |
| Advanced → IAM instance profile | `CarPriceEC2Role` |
| Advanced → User data | Paste the whole of `deploy/ec2-user-data.sh` |

Launch, wait about 3 minutes, then check the agent: select the instance → *Connect* → *EC2 Instance Connect* (or *Session Manager*):

```bash
systemctl status codedeploy-agent      # should be "active (running)"
```

If it's not running, see Troubleshooting below.

## 5. Create the CodeDeploy application

CodeDeploy → *Applications* → **Create application**
- Name `car-price-app`, compute platform **EC2/On-premises**.

Open it → **Create deployment group**:
- Name `car-price-dg`
- Service role `CarPriceCodeDeployRole`
- Deployment type **In-place**
- Environment configuration: **Amazon EC2 instances**, tag `App` = `car-price` (it should say *1 unique matched instance*)
- Agent configuration with AWS Systems Manager: **Never** (user data already installed the agent)
- Deployment settings `CodeDeployDefault.AllAtOnce`
- Load balancer: **untick** *Enable load balancing* (a load balancer costs extra)

## 6. Create the pipeline (this also creates the CodeBuild project)

CodePipeline → **Create pipeline** → *Build custom pipeline*:

**Pipeline settings**
- Name `car-price-pipeline`; execution mode *Superseded*; *New service role*.

**Source**
- Provider **GitHub (via GitHub App)** → *Connect to GitHub* → authorise → pick your repo, branch `main`
- Trigger: start the pipeline on push.

**Build:** provider **AWS CodeBuild** → **Create project** (opens a new window):

| Setting | Value |
|---|---|
| Project name | `car-price-build` |
| Environment | Managed image → **EC2** → OS **Ubuntu** → runtime *Standard* → image `aws/codebuild/standard:7.0` |
| Compute | **3 GB memory, 2 vCPUs** (`build.general1.small`). *Only this size is in the free tier.* |
| Service role | New service role (note its name, e.g. `codebuild-car-price-build-service-role`) |
| **Additional configuration → Environment variables** | Name `MODEL_BUCKET`, Value *your bucket name from step 2*, Type *Plaintext* |
| Buildspec | *Use a buildspec file* (it reads `buildspec.yml`) |
| Logs | CloudWatch logs on (default) |

Then *Continue to CodePipeline*.

**Test stage:** skip it (the tests already run inside the build).

**Deploy**
- Provider **AWS CodeDeploy**, application `car-price-app`, group `car-price-dg`.

Create the pipeline. **The first run will fail at Build with `AccessDenied`.** That's expected: the CodeBuild role can't write to your bucket yet. Fix it now:

IAM → *Roles* → `codebuild-car-price-build-service-role` → *Add permissions* → **Create inline policy** → *JSON* tab, paste this with your bucket name filled in, and name it `CarPriceModelBucketWrite`:

```json
{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Effect": "Allow",
      "Action": ["s3:ListBucket"],
      "Resource": "arn:aws:s3:::YOUR-BUCKET-NAME"
    },
    {
      "Effect": "Allow",
      "Action": ["s3:GetObject", "s3:PutObject"],
      "Resource": "arn:aws:s3:::YOUR-BUCKET-NAME/models/*"
    }
  ]
}
```

Back in CodePipeline, click **Release change**. The full run takes about 6–8 minutes the first time, mostly installing packages on the t3.micro.

## 7. Check it worked

- **Site:** EC2 → your instance → copy **Public IPv4 address** → open `http://<that-ip>/` (use `http://`, not `https://`).
- **Model came from S3:** `http://<ip>/model-info` should show `"source": "s3://your-bucket/models/builds/1"` and `"loaded": true`.
- **S3 console:** your bucket shows `models/builds/1/` (model, options, metrics) and `models/latest/`.
- **API docs:** `http://<ip>/docs`

## 8. Show the CI/CD working

Change something visible (for example the subtitle in `frontend/index.html`), then:

```powershell
git commit -am "Update subtitle"
git push
```

Watch CodePipeline go Source → Build → Deploy, then refresh the site. A new `models/builds/2/` folder appears in S3, and `/model-info` points to it.
If a test fails, the Build stage turns red, nothing is uploaded to S3, and the live site is **not** touched.

## Cost guardrails

| Service | Free allowance | This project's usage | Watch out for |
|---|---|---|---|
| EC2 t3.micro | 750 h/month (legacy, 12 months) or paid from credits (Free plan) | 1 instance × 744 h = within limit | A **second** instance doubles the hours |
| Public IPv4 | Legacy tier includes 750 h/month; on the Free plan it's paid from credits ($0.005/h ≈ $3.6/month) | 1 address | Don't allocate an **Elastic IP** (charged when unattached) |
| EBS gp3 | 30 GB | 8–20 GB | Leftover volumes from terminated instances |
| CodeBuild | **100 min/month, always free** on `general1.small` | ~3 min per build → ~30 builds/month | Choosing a bigger compute size |
| CodePipeline V2 | 100 action-minutes/month | ~6–8 min per run → ~12–15 runs/month | Beyond that: $0.002/min (≈ ₹0.17) |
| CodeDeploy (to EC2) | Free | — | — |
| S3 (model bucket) | 5 GB storage, 2,000 PUT, 20,000 GET per month (legacy) | ~18 MB × builds kept for 30 days; ~7 requests per build | Skipping the lifecycle rule |
| S3 (pipeline artifacts) | Same allowance | ~5 MB per run (model is no longer in the bundle) | Add the same kind of rule: the `codepipeline-ap-south-1-…` bucket → *Management* → expire after 7 days |
| CloudWatch Logs | 5 GB | KBs per build | — |

S3 traffic between EC2 and S3 in the **same region** is free. That's another reason to keep everything in Mumbai.

**Never create these** for this project: Application Load Balancer, NAT Gateway, RDS, an unattached Elastic IP, or a CodeBuild size above 3 GB.

## When you're done (after grading)

1. CodePipeline → delete `car-price-pipeline`
2. CodeBuild → delete `car-price-build`
3. CodeDeploy → delete `car-price-app`
4. EC2 → **Terminate** the instance (stopping still keeps its disk). Check *Volumes* is empty.
5. S3 → **empty** and delete your model bucket and the `codepipeline-ap-south-1-…` bucket
6. CloudWatch → *Log groups* → delete `/aws/codebuild/car-price-build`

## Troubleshooting

| Symptom | Fix |
|---|---|
| Build fails: `MODEL_BUCKET environment variable is not set` | CodeBuild → `car-price-build` → *Edit* → *Environment* → *Additional configuration* → add `MODEL_BUCKET`. |
| Build fails in **POST_BUILD** with `AccessDenied` / `upload failed` | Add the inline policy from step 6 to the CodeBuild role and check the bucket name in it matches exactly. |
| Deploy fails at **ValidateService**; `/predict` says *Could not download s3://…* | The EC2 role is missing or can't read the bucket. Check the instance has `CarPriceEC2Role` with `AmazonEC2RoleforAWSCodeDeploy`. |
| Deployment fails immediately: *no instances found* / *agent not running* | Check the instance has the tag `App=car-price` and role `CarPriceEC2Role`, then `sudo systemctl restart codedeploy-agent`. If you attached the role after launch, restart the agent. |
| Agent not installed | Run the lines of `deploy/ec2-user-data.sh` manually with `sudo bash`. Setup logs are in `/var/log/cloud-init-output.log`. |
| Build fails: *runtime version not supported* | In `buildspec.yml` change `python: 3.12` to `python: 3.11`. |
| Deploy fails at **AfterInstall** | Usually low memory or no internet. Check `free -h` (swap should show 1 G) and `/opt/codedeploy-agent/deployment-root/deployment-logs/codedeploy-agent-deployments.log`. |
| Any other ValidateService failure | The script prints the app logs. You can also see them with `journalctl -u car-price -n 100`. |
| Site doesn't load in browser | Security group must allow inbound **80**. Use `http://`. |
| Site IP changed | Stopping and starting the instance gives it a new public IP; that's normal. |
| Free plan account: a service says it isn't available | Some services may be restricted on the Free plan; upgrading to the Paid plan keeps using your remaining credits. |
